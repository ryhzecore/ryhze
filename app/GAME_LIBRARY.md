# Windows game library - 1.1.2 (10)

Games contains one shared catalogue. Installed games is a category in its Category filter, alongside All games and the existing catalogue genres. Local titles use RyhzeTitleCard and ArtworkHero directly, including the artwork overlay, footer, hover/focus effects and reduced-motion preference. Manage games contains permission setup, scanning, manual paths and preferences. The first launch asks for permission before reading installation records or game activity; declining is remembered.

Automatic discovery reads Steam's registered installation and libraryfolders.vdf, then installed app manifests on all configured volumes. Epic's installed .item manifests supply game and launcher identities. Riot's associated-client records locate installed Valorant; it launches using Riot Client's required product arguments. Missing volumes, invalid manifests and incomplete Epic installs do not prevent other games appearing. Users can add additional Steam library folders and manually select game executables using the Windows file chooser or a full path. Shared launcher executables are rejected as manually tracked games.

Only local preferences store game paths and last-played timestamps. There is no library upload or account sync. With permission, Windows process snapshots are read every five seconds while Ryhze is open. Steam game detection requires a visible window beneath the game's own installation folder and excludes launcher/helper executables. Manual games match their full executable paths; Epic and Riot also know their actual executable. Last played changes on observed game start/exit, not on a launch-button click. Restarting Ryhze reattaches to games that are still running. It cannot reconstruct play sessions while Ryhze was closed.

Resume restores and foregrounds the detected game window. Close game sends WM_CLOSE; Force stop requires an explicit choice warning about unsaved progress and terminates only identified game processes. Each native action revalidates both the executable path and process creation time before acting, preventing PID reuse from affecting unrelated apps. Windows can deny access to elevated or protected game processes; the UI reports that limitation instead of claiming success. No administrative escalation, game injection, anti-cheat bypass, or shared-launcher termination is used.

Steam's public store API provides official artwork, all supplied screenshots and playable trailer URLs. Media for non-Steam games is used only when there is one exact normalized title match, and is credited to Steam. A manually added game may specify its Steam app ID to disambiguate. Store metadata is cached locally for seven days; transient errors fall back to the cache. Riot's supplied official Valorant art is reused. Store-exclusive, delisted, restricted, and unavailable galleries retain a neutral game icon and original-store link instead of unrelated artwork. Media requests send game names or store IDs to Steam, as disclosed in the permission prompt; paths, process identities and play history are never sent.

Steam/Epic automatic discovery does not mean every PC launcher exposes an accessible catalogue. Other games can be added as executables. Store-dependent games still require their original launcher/account, and special launch arguments or executable changes can require configuration in that launcher.

Verification includes multi-library and malformed-manifest fixtures, path-boundary/process filtering, permission denial and revocation during an in-flight snapshot, history restoration, invalid-path rejection, media provenance/cache checks, responsive library/detail screens, and actual Windows process launch/resume/graceful close/force stop tests with an isolated test executable. The fixture and screenshots are excluded from distribution.
